01 — 실척 미리보기 (real scale)

보강안 — 크게 보기

실척으로 렌더링합니다 — 기준 뷰포트 1440 × 900(헤더·푸터 60px 등 실제 크롬 치수)를 그대로 그린 뒤 화면 폭에 맞춰 비례 축소만 합니다. 따라서 03에서 조절하는 절대 px = 실제 1440×900 화면의 값입니다. 드롭다운으로 현재 · 방안 A · 방안 B 전환, 03 슬라이더가 이 프레임에 즉시 적용됩니다.

방안 B(트레이): Screen3 작업 면(흰 패널)을 랜딩부터 띄워 카테고리 선택·도구 진입 내내 같은 크기로 지속시키는 안. 트레이 좌상단에 기존 "Ontab" 텍스트(88px)가 그대로 약간 비뚤게(책상에 툭) 놓이고, 중앙에 헤드라인+benefit. 탭은 현 위치 유지. ※ 이건 Screen2/3와 CONTEXT의 "Tray + Lid = 비물질" 계약까지 건드리므로 #4 첫 화면 보강 범위를 넘는 큰 결정 — 여기선 느낌만 보고, 채택 여부는 따로 정합니다.

02 — 첫 화면 진단

지금 첫 화면이 말하는 것 / 아직 안 보이는 것

브레인스토밍을 위한 중립적 분석입니다(아직 제안 아님). 오른쪽 항목들은 CONTEXT.md·i18n에 이미 존재하지만 첫 화면에는 노출되지 않은 것들 — "보강" 후보가 여기서 나옵니다.

이미 첫 화면에 있는 것

  • 브랜드 — 헤더 워드마크(마크+Ontab), 히어로 "Ontab" 88px
  • 한 줄 설명 — "브라우저 탭 위에서 작동하는 문서 도구" landing.descriptor
  • 카테고리 진입 — 프레젠테이션 · 문서 · 이미지 3탭
  • 언어 · 테마 — KO/EN 토글, 라이트/다크
  • "브라우저 안에서 동작" — 단, 푸터에만 작게 footer.copyright

아직 첫 화면에 안 보이는 것 (보강 후보)

  • 무엇을 해주는 곳인지 — 구체 가치(PPT·PDF·이미지 빠르게 고치기)가 "문서 도구" 한 줄에 갇힘
  • 신뢰 요소 — 무료 · 로그인 없음 · 업로드 없음 · 무제한 status.* (CONTEXT 차별점인데 첫 화면 부재)
  • 도구 미리보기 — 어떤 도구가 있는지 카테고리 클릭 전엔 안 보임
  • 빠른 진입 — 대표 작업으로 바로 가는 경로 없음(항상 카테고리→그리드→도구)
  • 마크 활용 — 브랜드 마크가 헤더에만 작게, 히어로는 텍스트뿐
