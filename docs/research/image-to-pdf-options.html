이미지 → PDF: 다른 도구, 쓰이는 곳, 정할 수 있는 것

grill-with-docs 1라운드 전에 필요한 배경 자료입니다. 결정은 담지 않았습니다. 제안은 제 추천이고, 미확인은 출처가 약하거나 아직 재 보지 않은 것입니다.

한눈에

업계 표준 선택지는 세 가지입니다: 용지 크기, 방향, 여백.iLovePDF·Sejda·PDF Candy·Smallpdf·PDF24·Adobe가 모두 이 셋을 줍니다. 우리는 크기만 있고 방향·여백이 없습니다.
"이미지 크기 그대로" 페이지는 경쟁 도구도 모두 둡니다.iLovePDF "Fit", Sejda "Fit to image", PDF Candy "original". 이 선택지에 크기 제한을 두지 않겠다는 의견이 업계 관행과 맞습니다.
화질·용량 선택은 변환 도구에 거의 없습니다.PDF24는 아예 "압축 도구를 쓰라"고 안내합니다. 대신 PDF가 가는 곳(이메일, 제출 시스템)은 5~25MB 제한이 흔해서, 폰 사진 여러 장이면 넘기기 쉽습니다.
코드 확인 중 개인정보 문제를 발견했습니다.JPEG를 원본 그대로 넣기 때문에 사진의 EXIF(촬영 기기, 시각, 켜져 있었다면 GPS 위치)가 PDF 안에 그대로 남습니다. 제출·공유용 PDF에 집 위치가 들어갈 수 있습니다. 실제 폰 사진으로 확인 필요

1. 다른 도구는 어떻게 하는가

각 도구의 공개 페이지 기준입니다. 기본값을 밝히지 않은 곳은 비워 두었습니다.

도구용지 크기방향여백화질·용량묶기기타
Ontab (지금)이미지맞춤 · A4 · 사용자 지정(px라 적혀 있지만 실제는 pt)없음 (A4는 세로만)없음원본 그대로하나로만순서 바꾸기·회전·삭제, HEIC 받음

읽을 점

  • 방향 "자동"(사진이 가로면 가로 페이지)이 Sejda·PDF Candy의 기본입니다.
  • 여백은 거의 모두 "없음/작게/크게" 3단계이고, 기본은 "없음"입니다.
  • "이미지 크기 그대로"도 거의 모두 둡니다. 다만 그 페이지가 실제로 몇 cm인지는 어느 곳도 설명하지 않습니다.
  • 화질·용량을 묶어서 파는 곳은 없습니다. 이건 우리가 차별점으로 삼을 수 있는 자리이기도 하고, 아무도 안 하는 데 이유가 있을 수도 있는 자리입니다.

2. 만든 PDF는 어디로 가는가

CONTEXT의 대상 사용자 표를 기준으로, 결과 PDF가 가는 곳과 그곳의 제약입니다. 용량 수치는 공식 안내를 찾지 못한 것이 많아 미확인으로 표시했습니다.

가는 곳누가무엇을그곳의 제약중요한 선택지
학교 LMS·과제 제출학생, 교사(받는 쪽)필기·칠판·과제 사진 여러 장학교마다 용량 제한이 다르고 공개 수치를 찾지 못함 미확인용량, 순서
회사 경비·증빙 제출직장인영수증 사진홈택스·연말정산 업로드는 5~10MB라는 업체 글만 있음 미확인용량, A4, 한 장에 여러 장
민원·공공 제출모두서류 사진·스캔지자체 전자민원 5MB 사례(2015 국민신문고, 오래된 자료). 정부24 현재 수치 못 찾음 미확인용량, A4
이메일 첨부모두무엇이든네이버 메일 일반 첨부 10MB(블로그 기준), 넘으면 대용량 링크로 바뀜. Gmail 25MB용량
인쇄목회자(주보·악보 사진), 교사(학습지), 소상공인(메뉴)사진·이미지프린터는 가장자리 몇 mm를 못 찍음. 용지 크기가 맞아야 함A4/Letter, 여백, 방향
메신저·화면 보기모두공지 이미지 묶음뷰어가 화면 폭에 맞춰 보여 주므로 페이지 실제 크기는 거의 안 보임순서 정도
보관직장인, 소상공인영수증·계약서 사진장기 보관 규격(PDF/A)을 요구하는 곳이 있으나 개인 사용자에겐 드묾(낮음)

읽을 점

  • "화면으로 본다"면 거의 아무 선택지도 중요하지 않습니다. 선택지가 의미 있는 경우는 제출(용량)과 인쇄(용지·여백·방향) 두 가지입니다.
  • 폰 사진 한 장은 보통 2~5MB입니다. 원본 그대로면 3~4장만 넣어도 10MB 제한에 걸립니다.

3. PDF를 만들 때 정할 수 있는 것 전체

사용자에게 고르게 할지, 우리가 기본값으로 정할지는 칸마다 따로 판단할 일입니다. 오른쪽 칸은 제안이며 아직 결정이 아닙니다.

4. "이미지맞춤" 다시 보기

1라운드의 Q2(이미지맞춤 페이지를 A4 길이로 맞추자)는 거둡니다. 지적하신 대로 경쟁 도구가 모두 "이미지 크기 그대로"를 두고, 화면으로 보는 대부분의 경우 티가 나지 않습니다. 인쇄할 사람은 A4를 고르면 됩니다.

남는 영향 두 가지 (선택지를 바꿀 정도는 아님)

  • 해상도가 다른 그림을 섞으면 페이지 크기가 들쭉날쭉합니다. 스크린샷(폭 1170px)과 폰 사진(폭 4032px)을 같이 넣으면 페이지 폭이 약 3.4배 차이가 나서, 고정 배율로 보는 뷰어에서는 작은 페이지와 큰 페이지가 섞여 보입니다.
  • 크기 줄이기와 엮입니다. 그림을 줄일 때 페이지까지 같이 작아지면 안 되므로, 페이지 크기는 원본 기준으로 두고 그림만 줄여 넣어야 합니다. 이건 기술 결정이라 제가 처리합니다.

5. 아직 모르는 것

  • 제출처 용량 제한의 공식 수치 (LMS, 홈택스, 정부24). 업체 블로그 수준만 찾았습니다.
  • iPhone·Android 브라우저로 사진을 올릴 때 GPS가 실제로 남아 있는지. 폰 설정과 OS 버전에 따라 다릅니다. 실제 사진으로 확인할 일입니다.
  • PNG 압축 방식을 바꿀 때 실제로 얼마나 줄어드는지. 측정 전입니다.
  • 폰 사진을 DPI 단계별로 줄였을 때의 용량과 화질. 측정 스크립트(scripts/measure-image-prep/)를 재사용해 잴 수 있습니다.
