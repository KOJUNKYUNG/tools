## Problem

Replace the user's canva dependency in weekly church PPT work. The wedge: place
N images at a defined position/size on a chosen background, one image per slide,
output `.pptx`. Sister tool to `image-to-pdf` (PR #12) — only the output stage
(PDF → PPTX) differs. First tool of Phase 2's locked 5 (hard contract).

## Locked decisions (from /grill-me + /plan-eng-review, 2026-05-30)

### D1 — PPTX library: **pptxgenjs**
- Boring-by-default Layer-1 lib. ~700KB (in-band; pdfjs worker tier).
- Declarative `addSlide()` / `addImage({x,y,w,h,rotate,sizing})` in inches.
- Rejected: hand-rolled OOXML (jszip) — spends an innovation token poorly,
  lifelong compatibility debugging across PowerPoint/Keynote/Google Slides.

### D2 — Module boundary: **shared UI module + new output assembler**
- `src/components/pdf-editor/` (PageItemCard, buildPageItems, thumbnailCache,
  useLazyThumbnail) is output-agnostic → image-to-pptx imports it as-is.
- PDF/PPTX diverge only at the assembler. Add `src/lib/pptx/assemblePptx.ts`
  (pptxgenjs). Do NOT fork into `pptx-editor/` (DRY) and do NOT branch PPTX
  inside `assembleSections.ts` (keep pdf-lib file single-responsibility).
- `computeImageFit` geometry shared. Relocate `src/lib/pdf/imageFit.ts` →
  neutral path (`src/lib/common/imageFit.ts` or `src/lib/geometry/`) so a PPTX
  tool doesn't import a `pdf/` path. Update image-to-pdf/pdf-arrange imports.
  (Small, do in this PR for honesty.)

### Layout editor (Decision #3) — **define-once geometry, replicated to all slides**
- One reference image in the editor. User sets the placement box by:
  - **drag to move**, **corner-drag to resize**, AND
  - **right-panel numeric inputs: X, Y, W, H** (X,Y = box top-left corner).
  - Editor box ↔ numeric fields are **two-way bound** (live). Reuse
    image-resize's commit-on-blur + focus-tracking display pattern and
    CropSelector's 8-handle math + displayBox letterbox mapping (adapt from
    "crop region within image" → "placement box on slide canvas").
- The defined box (X,Y,W,H) + background applies to **every** uploaded image;
  one image per slide.

### D3 — Background (Decision #2): **image + solid color**
- Background = uploaded image OR solid color (color picker). Full-bleed bottom
  layer of every slide.
- Slide aspect: **16:9 default + 4:3 toggle** (church PPTs are sometimes 4:3).
- Gradient: deferred (angle/stop picker = over-engineered for v1).

### D4 — Multi-image (differing sizes): **fit-to-box, aspect-preserving, top-left anchored**
- Every image placed into the same box (X,Y,W,H), scaled to **contain**
  (preserve own aspect, no distortion, no overflow), anchored to the box's
  **top-left** (X,Y). Predictable; safe for the church case where 악보 scans
  are near-identical dimensions.
- Rejected: relative-scale/native×factor (overflow risk) and stretch (distorts
  악보 — illegible).

### D5 — Handoff (Decision #4): **ppt-extract → image-to-pptx**
- Add an `.handoff-action` "image-to-pptx로 보내기" button to ppt-extract's
  result → `stageFiles(extractedImages)`.
- image-to-pptx consumes staged files on mount via `consumeStagedFiles`
  (one-time consume + StrictMode-safe URL pattern from image-compress).
- Consumer is source-agnostic → future HEIC/resize → image-to-pptx works free.
- Junk extractions (logos, EMF placeholders) are deletable in the editor.

### D6 — Image embed: **downscale to slide display size, then embed**
- Resample each image to its on-slide size (cap e.g. 1280–1920px long edge) via
  canvas before embedding (reuse image-resize/compress resample tech).
- Background image embedded **once** (dedup), not per-slide.
- Prevents 45 × multi-MB → hundreds-of-MB pptx, OOM, FILE_SIZE_LIMIT overflow.

## Architecture

```
INPUT                      EDITOR (define once)                OUTPUT
images N ──┐                                                  
           ├─ buildPageItems ─ pdf-editor/ cards ─┐           
handoff ───┘  (shared, as-is)                     │           
                                                  ▼           
background (image|color) ──► [ slide canvas ] ◄── placement box (X,Y,W,H)
slide aspect (16:9|4:3)       drag/resize  ◄──►  right-panel X/Y/W/H (2-way)
                                                  │           
                                                  ▼           
                              computeSlidePlacement(box, imgNative, slide)
                              (pure, fit-to-box, top-left, → inches)
                                                  │           
                              downscale-on-embed (canvas resample, D6)
                                                  │           
                              assemblePptx (pptxgenjs): per image →
                              addSlide → addImage(placement) on background
                                                  │           
                                                  ▼  .pptx (download / handoff out: none v1)
```

## New files
- `src/lib/pptx/slideSize.ts` — 16:9 / 4:3 constants (EMU/inch).
- `src/lib/pptx/slidePlacement.ts` — `computeSlidePlacement(box, imgNative, slide)`
  pure fit-to-box (aspect-preserving, top-left anchored) → inches. **TDD.**
- `src/lib/pptx/assemblePptx.ts` — pptxgenjs assembler (downscale + background
  dedup + per-image slide). Integration-tested.
- `src/components/tools/image-to-pptx/` — ImageToPptx.tsx (clone of ImageToPdf
  skeleton), PlacementEditor.tsx (drag/resize + numeric), BackgroundPicker.tsx,
  SlideAspectSelector.tsx, ImageToPptxResult.tsx, labels.ts.
- Registry entry in `src/lib/constants.ts` (slug `image-to-pptx`, no aliasOf).
- i18n ko/en keys. Screen3Workspace `renderToolBody()` case.

## Test plan
- **Pure (node vitest, TDD — convention):**
  - `slidePlacement`: img wider than box / taller / equal ratio / box at slide
    edge (clamp) / degenerate(0/neg) guard; pt→inch + px→inch boundary.
  - `slideSize`: constants (trivial).
- **Integration (node or /qa):**
  - assemblePptx: N images → N slides (unzip via jszip, assert slide count);
    background=color and background=image each verified; output opens in
    PowerPoint (manual /qa).
  - handoff: consumeStagedFiles one-time + StrictMode double-mount safe.
- **UI (/qa, jsdom not installed):**
  - editor drag = numeric update; numeric input = box update (round-trip);
    commit-on-blur; background swap preserves box coords.
  - ppt-extract "보내기" → handoff e2e.
- No regression tests (new tool, 0 change to existing behavior) — but verify the
  `imageFit.ts` relocation doesn't break image-to-pdf/pdf-arrange imports.

## Failure modes
| Codepath | Failure | Test | Error handling | User sees |
|---|---|---|---|---|
| assemblePptx | OOM (bulk/large) | — | D6 downscale + useToolProcessor gen guard | ProcessingStatus (not silent) |
| pptxgenjs gen | throw on bad bytes | needed | getErrorMessage toast | clear toast |
| handoff consume | empty stage / StrictMode double | **critical — must integ-test** | one-time consume + URL pattern | images appear once |
| background embed | dedup fail → N× bloat | integ (media count) | — | large file (caught by D6 cap) |

## NOT in scope (deferred)
- Gradient background → 확장 백로그.
- Per-slide individual placement (full canvas editor) → post-v1.
- Multiple images per slide → wedge is 1 image/slide.
- User-facing embed quality/size control → default downscale suffices; backlog.
- Bidirectional handoff (image-to-pptx → other) → no downstream tool, YAGNI.
- `pdf-editor/` → `page-editor/` rename → import churn; optional TODO.

## Parallelization
- Lane A: `lib/pptx/` (slidePlacement TDD → assemblePptx) — foundation.
- Lane B: editor + background picker UI (depends on A's placement).
- Lane C: ppt-extract "보내기" handoff button (independent).
- A + C parallel-capable; B after A. Single PR → sequential A → B → C.
