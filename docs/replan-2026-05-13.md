## Problem Statement

Phase 0(silver 디자인 + i18n + 인터랙티브 랜딩)이 머지·배포 완료된 상태에서 Phase 1(도구별 마이그레이션) 진입 직전. 진행 중간에 디자인 방향 전환(wood → silver)과 플러그인 도입이 겹쳐, **메모리는 최신이지만 `docs/`가 부분 stale**한 상태. 다음 세션이 길을 잃거나 mattpocock 라우팅이 풀파워로 동작하지 않을 위험을 제거하고 Phase 1을 깨끗하게 시작할 수 있게 한다.

## What Makes This Cool

이번 리플랜의 결과로 다음이 동시에 성립한다:

- 다음 세션이 `CONTEXT.md` 한 장으로 도메인 언어(silver/tray+lid/Phase 단위/도구 slug)를 즉시 흡수
- mattpocock 스킬군(`/grill-with-docs`, `/to-prd`, `/triage`, `/improve-codebase-architecture`)이 풀파워로 동작할 수 있는 인프라 확보
- `PRD_Z.md`가 실제 시행된 silver 로드맵과 일치 → 새 세션에서 PRD 읽고 헷갈리지 않음
- README가 "create-next-app 기본값"에서 "Ontab" 정체성으로 바뀜 — 오픈소스 공개 가능 상태

## Constraints

- **OS:** Windows + PowerShell (Unix-only 문법 금지)
- **언어:** 코드/문서 영어, 설명/대화 한국어 (글로벌 지침)
- **Stack:** Next.js 16(App Router, `proxy.ts`/`[lang]` 세그먼트), React 19, Tailwind 4, TS 5, pnpm. `AGENTS.md` 지시상 `node_modules/next/dist/docs/` 우선 참조
- **수익 모델:** 로그인·유료 티어 없음. AdSense 최후순위 (PRD §8 명시)
- **시각 충실도 contract:** `ontab_design/`의 inline style/매직 넘버/transition 값은 verbatim 보존
- **현재 라우트 구조 보존:** `src/app/[lang]/(chrome)/tools/{slug}` — 트레이 사진 풀블리드 유지의 핵심이라 재편 금지
- **최종 실행 모델 — 랜딩 인라인 (핵심 contract):** 도구는 최종적으로 **랜딩 페이지를 벗어나지 않고** Screen3Workspace 내부에서 업로드·처리·다운로드까지 완결되어야 한다. `[lang]/(chrome)/tools/{slug}` 라우트는 **직링크/SEO/하위호환용**으로만 유지되며, 마이그레이션이 완료된 도구는 동일 컴포넌트를 Screen3Workspace와 직링크 페이지 양쪽에서 재사용한다. Phase 1 마이그레이션 시 도구별로 Screen3Workspace의 임시 `Link → /{locale}/tools/{slug}` 브릿지를 **인라인 기능 호출**로 교체하는 것이 작업 단위. 메모리 `ontab_phase_progress.md`의 "Phase 0 → Phase 1 브릿지" 섹션과 일치.

## Approaches Considered

### Approach A — 최소 정리
PRD §8 갱신 + stale archive + README 1-pass. mattpocock은 나중. **Pros:** Phase 1 진입 최단. **Cons:** 다음 세션 mattpocock 풀파워 X, IMPROVEMENTS.md 그대로 남음.

### Approach B — 완전 정비
A + mattpocock setup + ADR 3개 + IMPROVEMENTS.md 10개 ticket 일괄 분해 + README 완전 재작성. **Pros:** 진입장벽 0. **Cons:** 분량 큼, Phase 1 머지 며칠 늦어짐, 도구 컨텍스트 없는 ticket 만들 위험.

### Approach C — 하이브리드 (선택됨)
mattpocock setup + **CONTEXT.md만** + ADR **1~2개만** + PRD §8 갱신 + stale archive + README **사용자 facing 핵심만**. **IMPROVEMENTS.md는 Phase 1 도구 마이그레이션 중 그 도구 항목만 점진 ticket화.**

## Recommended Approach — C

mattpocock 라우팅이 글로벌 지침에 명시돼 있어 인프라(CONTEXT.md)는 깔아야 진가가 나온다. IMPROVEMENTS.md 일괄 분해는 도구별 컨텍스트 없이 ticket 만들 위험이 있어 실제 도구 작업 사이클에 흡수하는 게 합리적.
